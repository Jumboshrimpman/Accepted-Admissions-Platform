# Fail-closed session pre-work dedupe

Owner: Cos (ops). Students: Taito Goto English (Oct 23 / Nov 13 / Dec 4) and SAT routine dates (including Oct 9 Grammar and Boundaries).

`ensureSeedData` → `ensureTaitoEnglishSessionPrework` / `ensureSatAssessmentSeed` / booking `ensureAutogeneratedSatPrework` must not insert another **live** before-session homework when that session already has one of the same kind (diagnostic vs routine). An empty published row still counts. Re-running seed is idempotent.

This does **not** rematerialize SAT/IELTS banks, scrape official exams, or send Clerk invites. Explicit admin assign (Curriculum → Sessions) still archives existing pre-work and replaces it.

## Cos one-shot: archive extras already live

Same pattern as `seed-taito-fall-agendas.ts`. No Clerk token. Run on the API host that already has `DATABASE_URL`:

```bash
cd artifacts/api-server
node --experimental-strip-types src/scripts/archive-duplicate-session-prework.ts --dry-run
node --experimental-strip-types src/scripts/archive-duplicate-session-prework.ts
```

Optional: `--course-id=<uuid>` if the Fall course title is not `Fall 2026 SAT & IELTS`.

Dry-run prints each session with extras, the keeper (newest complete assignment), and ids that would be archived. The apply run sets those extras to `archived` and retargets `session_prework_plans` to the keeper.
